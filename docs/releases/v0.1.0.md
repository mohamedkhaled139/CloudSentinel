# CloudSentinel v0.1.0 — first public release

CloudSentinel is a self-hosted, vendor-independent infrastructure health and availability
intelligence platform. This first release covers monitoring, dependency mapping, incident
intelligence, risk detection and reporting in a single container.

## Highlights

- **Monitoring** – HTTP/HTTPS (incl. TLS expiry), TCP, Linux hosts (dependency-free push agent),
  Prometheus (PromQL thresholds) and Kubernetes (API, nodes, workloads, pods/restarts).
- **Topology** – services and infrastructure with dependencies, health propagation (*impacted*),
  blast-radius analysis and an interactive graph.
- **Incidents** – automatic detection after consecutive failures, lifecycle with acknowledgement,
  notes and resolution, evidence, auto-resolution, grouping and probable-cause correlation.
- **Risk intelligence** – recurring failures, availability below target, latency regression,
  restarts/reboots, certificate expiry, stale/inconclusive monitoring, coverage gaps, unreachable
  integrations — each with evidence and a recommendation.
- **Reports** – availability, MTTR, incident time and top problems for any range; PDF and CSV export.
- **Operations** – RBAC (viewer/operator/admin), encrypted integration secrets, audit log, retention
  policies, health/readiness probes, JSON logs, migrations for SQLite and PostgreSQL, Docker Compose.

## Getting started

```bash
docker compose -f deploy/demo/docker-compose.yml up --build   # demo with labelled synthetic data
```

See [installation.md](../installation.md) for production deployment.

## Known limitations

- One scheduler per database (no leader election yet).
- No notification channels yet (planned for 0.2).
- Reports compute from raw results; rollups are planned for large installations.

## Verification

This release was tested with the automated suites (backend on SQLite and PostgreSQL 16, frontend,
agent on Python 3.8) and an end-to-end Docker run against real nginx and Prometheus containers.
